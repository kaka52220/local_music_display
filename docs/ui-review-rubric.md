# UI 设计评审清单（Review Rubric）

> 用途：每次界面设计/修改后，严格按本清单逐项评审，输出**明确问题与可执行修改指导**，再据此修改。
> 评分：每项 0–3 分（0 缺失 / 1 有明显问题 / 2 基本合格 / 3 打磨到位）。总分低于 20 或存在任一 P0，判定"需修改"。

## 评审维度

### 1. 布局与对齐 Alignment
- 是否沿统一网格/基线排列，元素边缘是否对齐，有无"差几个像素"的错位。
- 检查：控制条各分组是否垂直居中、列表表头与内容列是否对齐。

### 2. 视觉层次 Hierarchy
- 主次是否一眼可辨：当前曲目/主操作是否成为视觉焦点，次要信息是否弱化。
- 检查：标题、歌名、辅助文字的字号/字重/颜色是否形成清晰层级。

### 3. 间距系统 Spacing
- 是否使用统一间距刻度（如 4/8/12/16/24），同类元素间距是否一致。
- 检查：图标与文字、模块之间、容器内边距是否成比例，无随意数值。

### 4. 对比与可读性 Contrast
- 正文与背景对比度是否足够（目标 ≥ 4.5:1），弱化文字是否仍可辨。
- 检查：灰色辅助文字在深色背景上是否过暗，强调色是否仅用于重点。

### 5. 一致性 Consistency
- 颜色、圆角、字号、图标线宽、按钮风格在全界面是否统一。
- 检查：两个视图（列表/黑胶）的播放控件是否同一套视觉语言。

### 6. 亲密性与分组 Proximity
- 相关元素是否靠近、无关元素是否拉开，模块边界是否清晰。
- 检查：封面与歌名是否成组、控制按钮与进度条的归属关系。

### 7. 留白与平衡 Whitespace & Balance
- 有无大块无意义留白、单侧堆积、上重下轻；留白是否服务于分组。
- 检查：黑胶视图左右两栏是否视觉均衡。

### 8. 组件状态与反馈 States & Feedback
- 交互元素是否具备 hover / active / disabled 状态，点击是否有即时反馈。
- 检查：播放/暂停图标是否唯一且随状态正确切换（不重叠）。

### 9. 可访问性与响应式 A11y & Responsive
- 点击热区是否 ≥ 36px、键盘焦点是否可见、窄屏是否可用且不溢出。

## 评审输出格式

```
结论：通过 / 需修改
P0 必改：（编号列出，含具体位置与修改指导）
P1 建议：（编号列出）
评分表：维度 1–9 各项得分 + 总分
```

## 判定规则
- 任一 P0 问题 → 必须修复后重新评审。
- 总分 ≥ 24 且无 P0 → 通过。
- 20–23 且无 P0 → 可交付，P1 项记录待优化。
